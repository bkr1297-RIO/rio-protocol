## Data and Privacy Boundary

“Data, not doctrine” begins with a prior question: **whose data, under what consent, stored where, and used for what effect?**

This intake does not authorize a system to automatically ingest personal cycles, biometrics, journals, relationships, voice, location, birth data, or symbolic material. Any such collection requires a separate, scoped, revocable consent and data-handling specification.

A calendar record is not causal proof. A user-selected lens is not a profile. A receipt for an observation is not proof of the observation’s ultimate meaning or external-world truth.

The existing Rhythm Context candidate remains the public-safe entry point:

~~~text
fact context
  -> human-selected lens
  -> candidate observation
  -> human disposition
  -> optional separate Proposal Packet
  -> RIO only if a consequential crossing is requested
~~~

Its schema requires authority_effect: "none".
