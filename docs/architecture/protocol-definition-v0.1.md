# Protocol Definition — v0.1

## Formal Definition

A protocol is a finite, explicit set of rules that determines which
transitions are valid between defined states.

## Plain Language

A protocol says what may happen next, under what conditions, in what order,
and what counts as valid or invalid.

## Minimal Requirements

A protocol must define:

1. **Actors / Components** — who or what participates
2. **Allowed Inputs** — what can enter the system
3. **Rules of Movement** — what transitions are permitted
4. **State Transitions** — how the system moves between states
5. **Validation Criteria** — what counts as valid or invalid

## Boundary

A protocol is not merely a prompt, workflow, suggestion, habit, preference,
goal, belief, vibe, intention, or style guide. Those may inform a protocol,
but they are not the protocol.

## Learning / Permission Boundary

Protocol outcomes, receipts, logs, and observed patterns may improve future
support, surfacing, or protocol suggestions. They do not create consent,
authorization, standing permission, or authority transfer.

Learning improves support. It does not create permission.

## Keeper Lines

- A protocol is the governed grammar of movement.
- A protocol is the rule-set that makes a crossing admissible.
- Protocols define valid movement. RIO governs consequence. Receipts prove
  crossings. The human remains authority.
- Human-led, protocol-bound, receipt-verified, tools downstream.

## How This Applies to RIO

RIO implements protocol governance at the execution boundary. Every action
that crosses from intent to consequence must satisfy a protocol: the intent
must be structured, the risk evaluated, the approval recorded, the
authorization token issued and validated, the execution controlled, the
receipt signed, and the ledger entry verified.

The protocol is not the code. The code implements the protocol. The protocol
is the set of rules the code must satisfy.

## What This Does NOT Claim

- This definition does not claim the full ONE product is complete.
- This definition does not constitute legal or regulatory certification.
- This definition does not imply all governance is production-ready.
- The protocol definition is a design constraint, not a marketing claim.
